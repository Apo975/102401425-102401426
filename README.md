# 拾物 · 校园失物招领

第二次结对作业的 Web 实现：发布寻物/招领、浏览、关键词搜索、详情与联系方式、发布者更新状态。

## 运行方式

### 方式一：直接打开 HTML（本地演示）

下载完整仓库，用 Chrome 双击打开 `index.html`，无需安装 Node 或启动服务器。

数据只保存在当前浏览器的 localStorage，不会与其他电脑、浏览器或用户共享；同一存储来源的标签页通过 storage 事件刷新。file:// 下标签页存储隔离由浏览器决定，跨标签页演示推荐使用方式二。刷新后保留数据。

### 方式二：共享服务（推荐作业完整流程验收）

安装 Node.js 22 或以上版本，在仓库目录打开终端，运行：

```powershell
node server.js
```

用 Chrome 打开 `http://127.0.0.1:3000/`。也可运行 `npm start`，无需 `npm install`。服务默认只监听本机，数据保存在 `data/items.json`，重新启动后保留。关闭服务：终端按 Ctrl+C。

在普通 Chrome 与另一份浏览器配置或无痕窗口中打开同一个地址，就能验证两位用户共享列表：A 发布，B 浏览/搜索/查看联系方式，A 更新状态，B 点“刷新”或等待最多约 5 秒可看到新状态。保持服务运行，不要使用两个服务进程同时写同一个数据文件。

如果需要同一局域网的另一台电脑访问，可在 PowerShell 启动前设置：

```powershell
$env:HOST = '0.0.0.0'
node server.js
```

双方访问服务电脑的同一个局域网 IP 地址及端口，例如 `http://192.168.1.10:3000/`，不要把自己的 `127.0.0.1` 当成服务电脑地址。防火墙和网络隔离可能影响访问。可通过 `$env:PORT = '3001'` 更换端口。

本地演示数据和服务端数据互相独立，不会自动上传原 localStorage 内容。使用其他静态服务器或 GitHub Pages 不会提供本项目的共享 API；共享模式必须由 `server.js` 提供服务。

## 使用流程

1. 首页切换“寻物信息/招领信息”；勾选“只看我的发布”可维护自己的信息。列表按发布时间从新到旧显示。
2. 点“发布一条信息”，选择发布类型，填写名称、地点、时间和联系方式；类别和特征选填。缺项或超长内容会提示，成功后清空表单。
3. 搜索支持名称、地点、特征和类别；多个关键词必须全部匹配，英文大小写不敏感。空关键词浏览全部信息。可叠加类型、状态、类别及地点筛选。
4. 点击卡片查看详情，点“联系发布者”查看真实填写的联系方式。复制成功才提示成功；失败时手动选中文字复制。
5. 当前浏览器发布的信息才显示状态按钮：寻物标记“已找到”，招领标记“已归还”。完成后按钮禁用，首页、搜索及详情一致更新。
6. 顶部“访客预览”可快速查看无修改入口的界面，返回发布者恢复操作。它只是界面演示；真实服务端权限请用两个独立浏览器身份验证。

## 发布者身份与旧数据

首次打开会创建随机发布者凭据，保存在当前站点的 `lost_publisher_token`。共享服务只保存凭据摘要，返回列表不会泄露他人的凭据或归属摘要，更新接口在服务端重新检查归属。无需账号或实名认证。

同一浏览器配置、同一地址通常共用发布者身份；无痕窗口、不同浏览器配置、不同访问地址各有独立身份。清除站点存储会失去原发布者身份，旧信息仍可浏览但无法再修改。请保留原浏览器配置和访问地址。

旧版本的信息没有发布者记录，升级后保留为只读，不自动归属给当前浏览器。本地模式是教学演示，能直接编辑本机数据的人仍能修改归属；多人权限由共享服务保证。本项目没有账户找回和后台管理流程。

## 存储与故障处理

- 保存失败时不会显示成功，发布表单保留，状态保持原值；可释放磁盘/浏览器空间后重试。
- 服务断开时页面提示读取失败，恢复服务后点“刷新”。
- 本地保存内容损坏时不会自动清空或覆盖；先在 Chrome 开发者工具 Application → Local Storage 中备份 `lost_items` 原文，再修复为合法数组。若确定放弃旧数据，可手动删除该项或设为 `[]`，然后刷新；保留 `lost_publisher_token` 以保留身份。
- 服务端 `data/items.json` 损坏时停止启动，先复制备份，再修复文件，或移走损坏文件后重新启动生成空列表。不要直接覆盖未备份的数据。
- 图片上传不是此次核心要求，原来的未实现图片入口和占位图已移除。

## 自动化测试

Node.js 22+ 下运行：

```powershell
node --test tests/*.test.js
```

或 `npm test`。测试使用 Node 内置 `node:test` 和 `assert`，无需安装测试框架。测试启动随机本机端口，数据写入独立临时目录，不读取或修改作业的真实数据。

测试设计、覆盖边界、结果和手工 Chrome 验收步骤见 `TESTING.md`。本地自动化已通过 29 项测试；前端模拟测试不能替代真实 Chrome 界面验收。
